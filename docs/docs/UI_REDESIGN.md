# Knowledge Hub 介面改版規劃

狀態：P1、P2 完成並通過驗證，P2 待使用者審閱後 push（2026-11-24）· 分支：`ui-redesign` · Mockup：[Knowledge Hub 改版 Mockup](https://claude.ai/artifact/31WMjnFJBKW53DTCnq1vjr)（私人連結，需由擁有者分享）

本文件記錄介面改版的討論結論、mockup 內容與實作分期。改版只涉及前端呈現與資訊架構；後端 RBAC、HTML 沙箱與公開發布語意維持 `FINAL_MVP_SPEC_v2.1.md` 的規定，不因本規劃放寬。

## 1. 現況問題

依 M6 與「整站介面改版」後的前端（`frontend/src/*.vue`）盤點：

1. **沒有共用的 App Shell。** 每頁各自實作 `site-header`，導覽內容不一致：知識總覽有個人設定／帳號管理／登出，閱讀頁、版本歷史與回收桶只有「知識總覽」，帳號管理以 `<a href="/">` 整頁重載。進入文件後失去帳號選單與所在位置。
2. **功能入口分散且過深。** 回收桶與分類標籤管理是知識總覽標題旁的按鈕，帳號管理在頁首。「管理文件」對話框同時承擔改資料、公開設定、新增版本與移入回收桶；閱讀頁內無法執行這些操作。
3. **文件頁結構鬆散。** 版面選單、最大化、版本歷史（純文字連結）與下載混在同一列；左側「分類導覽」僅一兩個連結且與麵包屑重複；版本歷史是獨立頁、比較是彈窗，三者沒有被視為同一份文件的不同面向。
4. **清單能力不足。** 分類以全形空白模擬縮排，無法收合、無文件數；表格 7 欄、最小寬度 49rem，不能排序或批次選取；分頁只有上一頁／下一頁；上傳需先選「單檔／批次」模式。
5. **訪客與成員共用同一張管理表格。** 公開文章沒有摘要與日期，左欄只有「全部文件」。
6. **視覺與回饋細節。** 已定義 `--hub-*` token 但各頁仍寫死色碼；`darkModeSelector: false`；字型僅 `system-ui`，未指定中文字型；成功訊息常駐不消失；危險操作以「按兩次按鈕」確認。

## 2. 產品定位：三個介面

| 介面 | 對象 | 參考方向 | 設計重點 |
|---|---|---|---|
| 工作區 `/app/` | Viewer／Editor／Admin | Notion、Confluence、Outline | 資訊密度高、操作快、以文件為中心 |
| 公開知識站 `/` | 未登入訪客 | GitBook、Mintlify | 適合閱讀、品牌感、利於搜尋引擎、方便分享 |
| 管理主控台 `/app/admin/` | Admin（部分 Editor） | Linear 設定頁、GitHub Settings | 結構清楚、可稽核、危險操作明確隔離 |

三者共用設計 token，但版型、字級與密度各自獨立。

## 3. 資訊架構與路由

新介面在改版期間掛在 `/app/` 之下，與現有路由並存（見第 9 節）。

| 區域 | 路由 | 說明 |
|---|---|---|
| 工作區首頁 | `/app/` | 繼續閱讀、團隊最近更新、需要注意事項、集合概覽 |
| 全部文件 | `/app/library/` | 可排序、批次選取、每列「⋯」選單；篩選條件反映在網址 |
| 集合 | `/app/collections/:id/` | 集合說明加文件清單（取代「分類」的命名） |
| 文件 | `/app/docs/:id/` | 閱讀／編輯／分割預覽，右側 Inspector |
| 版本比較 | `/app/docs/:id/compare/?from=&to=` | 獨立整頁，可分享連結 |
| 已公開文章 | `/app/published/` | 公開版本與內部最新版本並列，標示落後 |
| 回收桶 | `/app/trash/` | 表格形式，支援批次還原 |
| 管理主控台 | `/app/admin/members/`、`/app/admin/taxonomy/`、`/app/admin/audit/`、`/app/admin/system/` | 見第 6 節 |
| 個人設定 | `/app/settings/` | 由頭像選單進入 |
| 公開站 | `/`、`/articles/:id/` | 獨立的 `PublicLayout` |

Django 範本頁面（登入、密碼重設、MFA、Google 綁定）維持由後端提供，只套用一致的品牌樣式。

## 4. 工作區設計

### 4.1 App Shell（三欄）

```
┌────────┬──────────────────────────────────────┬─────────────────┐
│ ◆ Hub  │ 技術 / 後端                     ☆  ⋯  │ 資訊 版本 公開 活動│
│ 🔍 ⌘K  │ API 設計規範                          │ 狀態  ● 公開 v5  │
│ 首頁    │ Markdown · v7 · 陳怡君 · 3 天前        │       ⚠ 落後 2 版│
│ 全部文件 │ ──────────────────────────────────── │       [發布 v7]  │
│ 最近閱讀 │   正文（閱讀字級 17px，行寬 72ch）      │ 集合  技術/後端   │
│ 收藏    │                                      │ 標籤  API  規範   │
│ 集合 ▾  │                                      │ 本頁目錄          │
│ 已公開   │                                      │                 │
│ 回收桶   │                                      │                 │
│ 管理    │                                      │                 │
│ (頭像)  │                                      │                 │
└────────┴──────────────────────────────────────┴─────────────────┘
```

- **左側欄：** 品牌、⌘K 搜尋入口、首頁／全部文件／最近閱讀／收藏、集合樹（圖示、文件數、可收合、未分類）、已公開文章（顯示落後數）、回收桶、管理主控台、頭像選單（個人設定、登出）。依角色隱藏無權限項目，僅為整潔，權限仍由後端判斷。
- **中欄：** 只放內容本身。窄螢幕時左側欄堆疊或收合為抽屜。
- **右側 Inspector：** 與目前文件有關的資訊與操作，可收合。

### 4.2 文件頁

- 頂列：麵包屑、收藏、「公開設定」（開啟 Inspector 的公開分頁）、「編輯」（主要按鈕）、「⋯」（新增版本、下載原始檔、移入回收桶）、Inspector 開關。
- 標題區：標題、格式、版本、公開狀態（含「落後 N 版」）、最後更新者與時間。
- 檢視模式：閱讀／編輯／分割預覽的分段控制。編輯時上方顯示「尚未儲存的變更」、更新說明輸入框、「儲存為 vN」。
- 版面：拿掉左側分類欄（App Shell 已提供），版面寬度切換縮成單一圖示按鈕。
- **Inspector 分頁：**
  - 資訊：集合、標籤可直接編輯；格式與大小；建立與更新者；本頁目錄。
  - 版本：垂直時間軸（版本號、目前版本／公開中標記、更新說明、作者與來源、時間）。勾選兩個版本後出現「比較 vA → vB」，比較結果以整頁差異檢視顯示。可從此處還原（Editor 以上）。
  - 公開（Admin）：狀態卡顯示公開版本、內部最新版本與落後數；公開網址與複製；選擇要發布的版本；「比較公開版與最新版」；「發布 vN…」仍需確認步驟；下架放在分隔後的危險區。
  - 活動：此文件的上傳、編輯、還原、發布與標籤異動紀錄。
- HTML 文件：沿用現有沙箱 iframe（`sandbox="allow-scripts"` 與獨立預覽網址）及相容模式警示，不改變安全邊界。

### 4.3 工作區首頁

- 標題區：日期、問候、「新增 Markdown」、「上傳文件」。
- 繼續閱讀：最近開啟的 4 份文件卡片。
- 團隊最近更新：活動流，可篩選「全部／我的／發布」，顯示更新說明。
- 需要注意：公開文章落後內部版本的數量與清單、回收桶文件數。
- 集合概覽：各集合說明與文件數。

### 4.4 文件清單

- 標題區：文件數、集合數、「上傳」。
- 篩選列：搜尋框、集合／格式／標籤／可見性／更新者等 facet 下拉、排序。條件寫入網址，可存成「已儲存的檢視」（後續）。
- 表格欄位：選取、文件（格式圖示、標題、集合路徑）、標籤、可見性（公開／私人／公開·落後）、版本、更新（時間與更新者）、「⋯」選單。
- 批次操作列：勾選後浮出，提供移動到集合、加標籤、下載、移入回收桶、取消選取。
- 分頁：顯示筆數範圍與頁碼。
- **上傳匣：** 檔案拖入視窗任何位置即開始上傳，右下角非模態面板顯示每個檔案的進度、完成狀態與重複檔處理（略過／仍要新增）；依檔案數自動判斷單檔或批次，不再需要模式切換。新增版本仍需從指定文件發起，維持「不以檔名自動配對版本」的規定。

### 4.5 指令面板（⌘K）

搜尋文件並可直接執行動作（上傳、前往回收桶、切換集合、開啟設定）。第一階段僅搜尋文件與導覽。

## 5. 公開知識站

- 頁首：品牌、公開集合連結、「成員登入」。
- 首屏：標題、說明、大型搜尋框。
- 依集合瀏覽：集合卡片（說明、文章數）。
- 最新文章：集合標籤、發布日期、預估閱讀時間、標題、摘要；可依集合篩選。
- 文章頁：左側集合目錄、正文、右側本頁目錄；底部上一篇／下一篇、複製連結、更新日期。移除「標準／寬版／全頁」選單，改用單一良好預設。
- 公開 HTML 維持靜態閱讀版與 `sandbox=""`。
- SEO meta 與 Open Graph 需要後端輸出，與 `backend/documents/public_html.py` 一併評估。

## 9. 開發策略

- 在同一個 repo 的 `ui-redesign` 分支開發，不另開 repo 或 fork：後端、Compose、Nginx、CI 與規範文件共用，改版以 PR 合回 `main`。
- 新介面掛在 `/app/`，舊介面 `/library/` 等路由照常運作，`main` 隨時可部署。新版驗收後再將首頁與舊路由導向新版，最後移除舊頁面。
- M7 NAS 部署在 `main` 進行；`ui-redesign` 定期 rebase 跟上 `main`。需要同時執行兩版對照時使用 git worktree。

### 10.2 P3 細項

P3 的範圍：公開知識站首頁、文章頁、SEO meta。只動公開的部分，成員介面 `/app/` 和舊頁面都不受影響。

| 子階段 | 內容 |
|---|---|
| P3a 後端 | 見下方「P3a 後端」 |
| P3b 公開首頁 | 見下方「P3b 公開首頁」 |
| P3c 文章頁與 SEO | 見下方「P3c 文章頁與 SEO」 |

**P3a 後端**

- 公開文章清單 `GET /api/public/articles/`：
  - 每篇文章新增 `excerpt`、`reading_minutes`、`published_at`、`collection` 四個欄位：
    - `excerpt`：取自 `search_text` 的前 120 字。
    - `reading_minutes`：中文以每分鐘 400 字估算。
    - `collection`：只有 `{id, name, color}`。
  - 新增 `collection=<id>` 參數，用來依集合篩選。
- 新增 `GET /api/public/collections/`：只列出有公開文章的集合，包含名稱、色標和公開文章數。
- 單篇 `GET /api/public/articles/:id/`：
  - 新增 `published_at`、`reading_minutes`、`collection` 三個欄位。
  - 新增 `siblings`：同一集合裡的公開文章，只回傳 id 和標題，依發布時間排序，前端用來做上一篇／下一篇和左側目錄。
- Django 新增 `/articles/`，跟現有的 `/articles/<id>/` 一樣，用 X-Accel 送出 SPA。
- 不需要資料遷移。所有新欄位都在查詢時計算，從既有的 `ArticlePublication` 和文件目前所在的集合取得。
- 每個端點都要測：
  - 訪客可以讀取。

**P3b 公開首頁**

**P3c 文章頁與 SEO**

- 文章頁 `/articles/<id>/`：
  - 左側是同一集合的文章目錄。
  - 正文使用單一閱讀版型，拿掉現在的「標準／寬版／全頁」選單。
  - 右側是本頁目錄。
  - 底部有上一篇／下一篇、複製連結、更新日期。
- 公開的 HTML 文章維持靜態閱讀版，iframe 用 `sandbox=""`。
- SEO：後端在 `/articles/` 和 `/articles/<id>/` 的 HTML 輸出 `<title>`、`description`、Open Graph（`og:title`、`og:description`、`og:type`、`og:url`）。
  - 優先嘗試的做法：Django 在 X-Accel 回應的 header 裡帶 meta，非 ASCII 字元先轉成 HTML 實體，再由 Nginx `sub_filter` 插入 `index.html`。
  - 如果 Nginx 在內部轉址後讀不到 upstream header，改用備案：讓後端讀取建置出來的 `index.html`，自己插入 meta。
  - 不論哪種做法，插入的內容都要經過 HTML escape，並且要測試惡意標題（例如含 `<script>`）。
- 舊的 `PublicArticle.vue` 等到 P4 切換路由時才移除。P3 完成後，`/articles/<id>/` 會直接改用新頁面。

  - 角色：訪客、Viewer、Admin。

  - 檢查項目：首頁、集合篩選、搜尋、文章頁（Markdown 和 HTML 各一篇）、上一篇／下一篇、SEO meta。

**刪除規則（第 12 節第 19 點）**

- 圖片只有在**所有版本都不再引用**時才會刪除。在編輯區刪掉的圖片，只要舊版本還引用就會保留，還原舊版本時不會破圖。
- 典型的孤兒圖片：貼上後沒有儲存就離開，或貼上又刪掉、從未進入任何版本。保留 24 小時的寬限期，涵蓋編輯到一半、復原（Ctrl+Z）、剪下再貼上等情況。
- 版本不會單獨刪除，所以實際上孤兒圖片只來自從未儲存的上傳，以及永久刪除的文件。

**權限與安全**

- **圖片歸屬於單一文件，權限跟著文件走：**
  - 登入成員：有該文件的閱讀權限才拿得到。
  - 訪客：只有該文件目前公開版本引用的圖片才拿得到；下架、移入回收桶後立刻拿不到。
  - **只計算圖片所屬文件自己的引用。** 文件 B 引用文件 A 的圖片時，不會因為 B 公開而讓 A 的圖片公開，避免透過複製連結洩漏私人文件的圖片。這種跨文件引用在沒有 A 權限的讀者那裡會顯示破圖。
  - 沒有權限時一律回 404，不透露圖片是否存在。
- **只收點陣圖：** PNG、JPEG、GIF、WebP。以檔頭判斷格式，不看副檔名或瀏覽器宣稱的類型。**不收 SVG**（可以夾帶 script）。
- **上限：** 單張 10 MB、4000 萬像素（防止解壓炸彈），每位使用者每小時 120 張。
- **伺服器端重新編碼：** 以 Pillow 依 EXIF 方向轉正後重新存檔，去掉 EXIF（手機照片的 GPS 位置等）與其他中繼資料，也能擋掉偽裝成圖片的檔案。動態 GIF／WebP 保留動畫。
- **同一份文件重複貼上同一張圖**（重新編碼後的 sha256 相同）只存一份，回傳既有的圖片。
- **回應標頭：** 固定 `Content-Type`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、`Content-Disposition: inline`。`Cache-Control: private, max-age=600`、`Vary: Cookie`：只存在瀏覽器、不給 CDN 快取。不用 `no-store`，因為分割預覽每次重繪都會重新載入圖片。
- 外部圖片維持現狀，Markdown 仍可引用任何外部網址的圖片（第 12 節第 20 點）。
- 圖片上傳不寫進活動紀錄，避免洗版；版本本身照常記錄。

**已知限制**

- 下載 Markdown 原始檔時，圖片是站內網址 `/api/images/<id>/`，離線開啟看不到圖。匯出含圖片的壓縮檔之後另行評估。
- 圖片檔案放在 `DOCUMENT_STORAGE/images/` 底下，M7 的備份範圍要包含這個目錄。

**驗證**

- 後端：
  - 上傳權限（Viewer、沒有編輯權限、文件在回收桶）、格式檢查（偽裝副檔名、SVG、損壞檔、超過大小和像素上限）、EXIF 被移除、去重、限流。
  - 讀取權限：成員有無閱讀權限、訪客對公開版本引用的圖片、下架後、跨文件引用不洩漏、不存在的 id 回 404。
  - 引用解析：編輯儲存、上傳 `.md`、還原舊版本都會記錄；不同寫法（相對網址、加 title、reference-style）都要能解析。
  - 清理：寬限期內不刪、仍被舊版本引用不刪、從未引用且超過寬限期才刪；文件永久刪除時連同圖片刪除；檔案和資料庫一致（`check_document_storage` 一併檢查圖片）。

  - P7a：工具列每個按鈕、快捷鍵、清單接續、貼上網址變連結、同步捲動、唯讀不顯示工具列；寬度 1920／1280／500 px 和深色模式。

  - P7c：系統狀態頁的圖片統計。
- 驗證用的圖片和文件在結束時清除。

**不納入 P7**

### 10.8 P8b 刪除單一版本

依使用者要求追加在 `p8-upload-tagging` 分支（第 12 節第 23 點）。原本的設計是「版本只增不減」，只能永久刪除整份文件。

**規則**

- 只有 Admin 能刪除。確認框要輸入版本號（例如 `v3`），可以填寫原因（選填，最多 200 字），確認後直接永久刪除，沒有版本回收桶。
- 不能刪除的版本：
  - **目前版本**：要刪的話，先用其他版本還原，產生新的目前版本後再刪。
  - **公開中的版本**：要先改發布其他版本或下架。直接刪除會讓資料庫連帶刪掉公開記錄，文章就會悄悄下架。
  - 回收桶裡文件的版本。
- 版本號不重新編排：刪掉 v3 後，版本歷史在原位置顯示「v3 已刪除・誰・什麼時候・原因」。
- 硬碟上的檔案在交易確認後刪除；刪檔失敗只寫記錄，留下的檔案由 `check_document_storage` 回報為多出的檔案。
- 被刪除的版本引用的圖片，如果其他版本都沒用到，會照 P7c 的規則在 24 小時後自動清掉。
- 舊連結（`?version=`、比較頁）指到已刪除的版本時，顯示「找不到這個版本，可能已被刪除」。
- 文件活動紀錄記一筆「刪除版本 v3」；稽核紀錄歸在「永久刪除」分類。
- 提醒：已經做過的備份裡仍然有這個版本。如果是因為敏感資料而刪除，備份也要另外處理（M7 備份策略）。

**資料表調整（遷移 0015）**

- `Version.restored_from` 原本是 `PROTECT`，被還原過的版本無法刪除。改成 `SET_NULL`，並新增 `restored_from_number` 保存版本號，讓「還原自 v3」在 v3 刪除後仍然看得到。
- `VersionRestoreAudit` 的三個版本關聯原本是 `CASCADE`，刪除版本會連帶刪掉還原稽核。改成 `SET_NULL`，並新增三個版本號欄位保存當時的數字。
- 既有資料在遷移時回填版本號。

**API**

- `POST /api/documents/<id>/versions/<version>/delete/`：`{"number": 3, "reason": "..."}`。`number` 必須和要刪的版本相符，避免刪錯。
- 版本歷史 `GET .../versions/` 多回傳 `deleted`：已刪除版本的版本號、時間、執行者、原因。

**驗證**

- 後端：只有 Admin、版本號不符時拒絕、目前版本／公開中版本／回收桶文件不能刪、檔案已刪除、還原來源被刪除後「還原自 v3」仍保留、還原稽核保留、活動與稽核紀錄、版本歷史的 `deleted`、被刪版本的詳細資料／下載回 404、圖片引用隨之移除、整份文件永久刪除仍正常。
- Playwright：Admin 看到刪除按鈕，Editor 看不到；目前版本和公開中版本按下刪除時只說明原因、不能確認；輸入錯的版本號不能確認；刪除後時間軸顯示已刪除的位置；舊連結的提示；500 px 與深色模式。測試使用暫時文件，結束時永久刪除。

### 10.10 P10 細項：Markdown 嵌入影片

P9 已在 2026-11-24 以 PR #5 合併回 `main`。P10 在 `p10-video` 分支開發，分兩個子階段，每個子階段完成後回報、確認後再 commit。

**目標**：在 Markdown 編輯區貼上、拖入或選擇影片檔，系統自動上傳並插入語法，預覽、閱讀頁和公開文章都直接顯示播放器。沿用 P7 圖片的整套作法：影片屬於單一文件、權限跟著文件走、引用追蹤、未使用 24 小時後清除（第 12 節第 25 點）。

**規格**

- 格式：只收 MP4 和 WebM，以檔頭判斷，不看副檔名或瀏覽器宣稱的類型。
  - MP4：第 4–8 位元組為 `ftyp`，主品牌不是 QuickTime（`qt  `），避免收進 `.mov`。
  - WebM：EBML 標頭（`1A 45 DF A3`），且 DocType 為 `webm`。
  - **不轉檔、不檢查編碼。** 檔頭正確但瀏覽器播不了（例如 iPhone 錄的 HEVC 編碼），播放器顯示「瀏覽器無法播放這段影片，請轉成 MP4（H.264）後重新上傳」。
- 上限：單檔 200 MB，每位使用者每小時 30 支。磁碟剩餘空間低於 2 GB 時拒絕上傳，並提示管理員清理。
- 同一份文件重複上傳同一個檔案（sha256 相同）只存一份，回傳既有的影片。
- 語法沿用圖片：`![影片說明](/api/videos/<id>/)`。Markdown 維持 `html: false`，不開放原生 `<video>` 標籤。
- 外部影片（YouTube 等）不支援（第 12 節第 25 點）。

**子階段**

| 子階段 | 內容 | 後端 |
|---|---|---|
| P10a 後端：上傳、播放、清除 | • 系統資訊頁的「儲存空間」分開顯示影片數量、佔用空間、待清理的未使用影片數<br>• 「立即執行維護」一併清理未使用的影片 | • 新增 `DocumentVideo`（所屬文件、sha256、格式、大小、上傳者、`uploaded_at`）與 `VersionVideo`（版本引用，`RESTRICT`）。**另建 model，不改動現有的圖片資料表**，避免遷移既有圖片<br>• `POST /api/documents/<id>/videos/`：Editor 以上、可編輯該文件；邊收邊算 sha256，不整檔讀進記憶體<br>• `GET /api/videos/<id>/`：Django 檢查權限後，回 `X-Accel-Redirect`，由 nginx 送檔（支援 Range，可以拖動進度條；不占用 gunicorn）<br>• 每次產生版本時，解析 `/api/videos/<id>/` 引用並記錄（編輯儲存、上傳 `.md`、還原）<br>• `collect_unused_images` 擴充成同時清理影片，規則相同；維護結果新增 `videos` 項目<br>• `check_document_storage` 一併檢查 `videos/` 目錄<br>• 文件永久刪除、刪除單一版本時，和圖片一樣處理 |
| P10b 編輯器與播放 | • 編輯區貼上、拖入影片，或用工具列新增的「插入影片」選檔<br>• 佔位文字顯示百分比：`![上傳中 35%…]()`；狀態列顯示「正在上傳影片 35%」<br>• **刪掉佔位文字就取消上傳**（中止請求，不在背景傳完）<br>• 影片上傳不設 180 秒逾時<br>• **上傳中不能儲存**：儲存列顯示「影片上傳中，完成後才能儲存」<br>• **上傳中離開頁面先確認**（切換頁面和關閉分頁都會提醒）<br>• 預覽、閱讀頁、公開文章把 `/api/videos/<id>/` 顯示成 `<video controls preload="metadata">`，寬度跟內文一致<br>• **分割預覽重繪時保留已存在的播放器**（依網址與順序對應），邊看影片邊打字不會被重置<br>• 播放失敗時，在播放器下方顯示轉檔提示 | 無 |

**送檔方式（nginx `X-Accel-Redirect`）**

- 目前 gunicorn 只有一個同步 worker。如果由 Django 直接串流影片，一個人在看影片就會卡住整個網站；Django 的 `FileResponse` 也不支援 Range。
- 做法：
  - Django 檢查權限，回應 `X-Accel-Redirect: /_protected/videos/<路徑>`，不傳檔案內容。
  - nginx 的 `location /_protected/videos/` 設為 `internal`（外部無法直接存取），`alias` 只指向 `videos/` 目錄，由 nginx 處理 Range 與傳檔。
  - `compose.yaml` 讓 nginx 以**唯讀**方式掛載文件儲存區。
  - nginx 在這個 location 加上 `X-Content-Type-Options: nosniff` 與 `Content-Security-Policy: default-src 'none'; sandbox`；`Content-Type`、`Content-Disposition: inline`、`Cache-Control: private, max-age=600` 由 Django 決定後帶過去。
- 上傳：`/api/documents/<id>/videos/` 的 `client_max_body_size` 放寬到 201m，其他路徑維持 51m。nginx 會先收完整個請求再交給 Django，連線慢的使用者不會占住 gunicorn。
- 部署文件補上 nginx 掛載儲存區的說明。

**權限與安全**

- 和圖片完全相同（10.6）：
  - 登入成員：有該文件的閱讀權限才拿得到；文件在回收桶就拿不到。
  - 訪客：只有該文件目前公開版本引用的影片才拿得到；下架後立刻拿不到。
  - 只計算影片所屬文件自己的引用，其他文件引用不會讓它公開。
  - 沒有權限、不存在時一律回 404。
- 公開文章的頻寬：播放器用 `preload="metadata"`，只有按下播放才會下載影片內容。
- 影片上傳不寫進活動紀錄，版本本身照常記錄。

**已知限制**

- 單一請求上傳，中途斷線要重新上傳，不支援續傳。
- 沒有縮圖：播放器顯示瀏覽器預設的第一個畫面或黑底。
- 影片檔放在 `DOCUMENT_STORAGE/videos/`，M7 的備份範圍要包含這個目錄；影片會讓備份大小明顯增加。
- 下載 Markdown 原始檔時，影片是站內網址，離線看不到。

**驗證**

- 後端：
  - 上傳權限（Viewer、文件在回收桶）、格式（`.mov`、偽裝副檔名、空檔、超過 200 MB）、磁碟空間不足、去重、限流。
  - 讀取權限：成員、訪客對公開版本引用的影片、下架後、跨文件引用不洩漏、不存在的 id 回 404。
  - 回應帶 `X-Accel-Redirect` 與正確標頭，不帶檔案內容。
  - 引用解析與清除：寬限期內不刪、仍被舊版本引用不刪、刪除版本後的處理、文件永久刪除時連同影片刪除、維護結果的 `videos` 項目。
- 透過 nginx 的實際測試：Range 請求回 206、直接存取 `/_protected/` 回 404。
- Playwright：
  - 拖入、選檔上傳，佔位文字的百分比變化，完成後預覽出現播放器並可播放。
  - 上傳中刪掉佔位文字會取消；上傳中不能儲存；上傳中離開頁面會確認。
  - 預覽重繪不重置播放器。
  - 不支援的格式、超過上限的通知；播不了時的轉檔提示。
  - 儲存後閱讀模式、公開文章可以播放；訪客看不到私人文件的影片。
  - 系統資訊頁的影片統計；寬度 500 px 與深色模式。
- 驗證用的影片和文件在結束時清除。

**不納入 P10**

- 伺服器端轉檔、縮圖、續傳、外部影片嵌入、HTML 文件的影片、字幕。

### 10.11 P11 細項：燈箱、相簿與相簿模式

P10 已在 2026-11-25 以 PR #6 合併回 `main`。P11 在 `p11-gallery` 分支開發，分五個子階段，每個子階段完成後回報、確認後再 commit。

**套件選擇（第 12 節第 26 點）**

- 採用 **PhotoSwipe 5（燈箱，MIT）＋ Embla Carousel 8（輪播，MIT）**；齊邊、方格、瀑布流、直列都用 CSS 和少量程式自己排版，不另外加套件。
- 評估過但不採用：
  - **lightGallery 3**：功能最完整，但授權是 GPLv3 或付費商業授權。本專案沒有採用 GPLv3，公開文章又會把程式傳給訪客，不符合「沒有授權問題」的條件。cssscript.com 介紹頁標示的「MIT」是錯的；套件本身和 npm 上的歷史版本都是 GPLv3。
  - **Fancybox 5**：同樣是 GPLv3 或商業授權。
  - **X3（photo.gallery）**：是獨立的商業 PHP 相簿網站系統，不是可以嵌入的套件。

速度倍率：快 × 0.75、標準 × 1、慢 × 1.25。每個時間乘上倍數後四捨五入到整數 ms；起始大小、曲線與背景暗度不隨速度改變。

**背景先出、圖片從中間浮現**（預設效果）

| 速度 | 背景淡入 | 圖片延遲 | 圖片浮現 | 圖片完全出現 | 關閉 |
|---|---|---|---|---|---|
| 快 × 0.75 | 225 ms | 113 ms | 488 ms | 約 600 ms | 300 ms |
| **標準** × 1 | 300 ms | 150 ms | 650 ms | 約 800 ms | 400 ms |
| 慢 × 1.25 | 375 ms | 188 ms | 813 ms | 約 1000 ms | 500 ms |

- 關閉：圖片先在「關閉」時間的 70% 內縮小到 92% 並淡出（曲線 `cubic-bezier(.4, 0, 1, 1)`），背景在「關閉」時間內淡出。

### 10.12 P12 細項：草稿自動保存

P11 已在 2026-11-25 以 PR #7 合併回 `main`。P12 在 `p12-draft-autosave` 分支開發。

**現況**：編輯 Markdown 時，內容只存在頁面的記憶體裡。瀏覽器當掉、分頁被誤關、電腦重開或斷線重新整理，未儲存的內容就會遺失。離開頁面雖然會先確認，但擋不住當機與強制關閉。

**做法：草稿暫存在這台電腦的瀏覽器裡**（第 12 節第 29 點）

| 項目 | 內容 |
|---|---|
| 何時暫存 | • 編輯區有未儲存的變更時，停止打字約 1 秒後暫存<br>• 切換分頁、關閉分頁或離開頁面時立即再存一次<br>• 不產生新版本，不寫進活動紀錄，不經過伺服器 |
| 存什麼 | 文件 id、草稿內容、編輯時依據的版本（id 與版本號）、暫存時間；以登入者的帳號 id 區分，不同帳號看不到彼此的草稿 |
| 何時刪除 | • 儲存為新版本後<br>• 按「捨棄變更」後<br>• 選擇「捨棄草稿」後<br>• 從工作區登出時，刪除這個帳號在這台電腦上的所有草稿<br>• 暫存超過 3 天自動刪除 |
| 狀態顯示 | 編輯列的「尚未儲存的變更」旁顯示「草稿已暫存 21:03」 |

**回到文件時**

- 有這份文件的草稿時，文件頁上方出現提示列：
  - 「你有一份尚未儲存的草稿（11/25 21:03 暫存）。」按鈕：**恢復草稿**／**捨棄草稿**／**下載草稿**（存成 `.md` 檔）。
  - 恢復後進入「分割預覽」，編輯區是草稿內容、狀態為「尚未儲存的變更」，照常按儲存產生新版本。
- **文件在這段期間已有新版本**（草稿依據 v3，目前是 v5）：提示列改為警告：「草稿是根據 v3 編輯的，之後已有 v4、v5。恢復並儲存，會以你的草稿內容成為 v6，v4、v5 的修改不會併入（仍保留在版本歷史中）。」建議先「下載草稿」或到版本歷史比對再決定。
- **草稿內容和目前版本相同**時（例如在別的分頁已經存過）：不提示，直接刪除草稿。
- **草稿中的圖片已被清除**：沒有存進任何版本的圖片，24 小時後會被系統清除。恢復時如果草稿引用的本站圖片已不存在，提示列會多一行「草稿中有 N 張圖片已被清除，需要重新貼上」。
- 正在看舊版本（`?version=`）、沒有編輯權限、HTML 文件時不提示，也不暫存。

**限制與取捨**

- **只存在這台電腦的這個瀏覽器**：換電腦或換瀏覽器就看不到草稿；清除瀏覽器資料、無痕視窗關閉後草稿也會消失。這是刻意的取捨：不必改後端，也不會讓未完成的內容離開這台電腦。
- **共用電腦**：草稿以帳號區分，登出時刪除；但沒有登出就關閉瀏覽器時，草稿仍留在這台電腦上，直到 3 天後過期或下次登出。
- **容量**：瀏覽器的儲存空間有限（通常約 5 MB）。單份草稿超過 2 MB 時不暫存，編輯列改為顯示「文件太大，無法暫存草稿」。
- **同一份文件開在兩個分頁**：以最後暫存的為準。
- 瀏覽器停用儲存功能時，暫存直接略過，不影響編輯與儲存。

**不採用的做法**

- **存在伺服器**：換電腦也能恢復，但要新增資料表與 API、定期清理，也會在伺服器留下未完成的內容；一般的當機與誤關，存在瀏覽器就足以涵蓋。之後有需要再另外評估。

**驗證**

- Playwright：
  - 打字後重新整理頁面：出現提示列；恢復後內容相同、狀態為未儲存、進入分割預覽。
  - 「捨棄草稿」後提示消失、重新整理不再出現；「下載草稿」得到內容正確的 `.md` 檔。
  - 儲存為新版本、按「捨棄變更」後，草稿被刪除。
  - 有新版本時的警告文字與版本號；草稿與目前版本相同時不提示。
  - 草稿引用已不存在的圖片時的提示。
  - 不同帳號看不到彼此的草稿；登出後草稿被刪除；超過 3 天的草稿不提示並被刪除。
  - 超過 2 MB 不暫存並顯示原因；瀏覽器停用儲存時編輯照常。
  - Viewer、舊版本、HTML 文件不提示；500 px 與深色模式。
- 驗證用的文件在結束時永久刪除。

**不納入 P12**

### 10.13 P13 細項：文件之間的連結與反向連結

P12 已在 2026-11-25 以 PR #8 合併回 `main`。P13 在 `p13-doc-links` 分支開發，分三個子階段，每個子階段完成後回報、確認後再 commit。

**連結格式（第 12 節第 30 點）**

- 文件連結就是標準 Markdown 連結，以文件 id 指向目標：`[BMC 韌體更新步驟](/app/docs/<id>/)`。
  - 改名、移動集合都不會斷；下載原始檔或用其他 Markdown 工具開啟時仍是可讀的連結。
  - 以下寫法都視為同一份文件的連結：`/app/docs/<id>/`、`/read/<id>/`、`/articles/<id>/`，以及前面加上本站網址（`PUBLIC_ORIGIN`）的完整網址。網址後面的 `?version=`、`#…` 不影響判斷。
- 不採用 Wiki 式的 `[[標題]]` 語法（改名就斷、同名無法區分、其他工具看不懂）；`[[` 只是編輯器裡的搜尋快捷方式，插入的仍是標準連結。
- 不支援連到文件中的某一節（章節編號會隨標題增減而改變）。

**子階段**

| 子階段 | 內容 | 後端 |
|---|---|---|
| P13a 連結記錄與反向連結 | • 文件頁資訊面板新增「連結」分頁：<br>　– 連到這裡的文件（標題、集合、更新時間），只列出看得到的文件<br>　– 這份文件連到的文件，失效的（在回收桶、已永久刪除）標示出來<br>• 閱讀頁與分割預覽中，文件連結前加小圖示；游標停留時顯示目標目前的標題與集合；失效連結加刪除線並說明原因<br>• 移入回收桶時（單份與整批），如果有其他文件連到它，確認對話框提醒「有 N 份文件連到這份文件，移入回收桶後這些連結會失效」 | • 新增 `VersionLink`（版本 → 目標文件 id）：每次產生版本時解析內容中的文件連結並記錄（編輯儲存、上傳 `.md`、還原、新增文件）；目標以 id 記錄，目標被永久刪除後仍保留紀錄以便標示失效<br>• 反向連結只計算各文件**目前版本**中的連結<br>• `GET /api/documents/<id>/links/`：`{incoming: […], outgoing: […]}`，成員才能讀；incoming 只含未在回收桶的文件；outgoing 含每個目標的狀態（正常、回收桶、不存在）<br>• 文件清單（目標的標題與集合）沿用讀取權限<br>• 資料遷移：為既有文件的目前版本補建連結紀錄 |
| P13b 編輯器插入 | • 輸入 `[[`：跳出文件搜尋清單（標題、所屬集合），邊打邊搜尋，Enter 插入 `[標題](/app/docs/<id>/)`（以選取的文字當連結文字，改由「選取後貼上文件網址」達成，見 P13b 實作紀錄）<br>• 斜線選單新增 `/連結文件`，效果相同<br>• 貼上本站的文件網址（上述任一種寫法）時，自動轉成 `[目前標題](/app/docs/<id>/)`；找不到或沒有權限時照原樣貼上<br>• 語法說明面板加入「文件連結」 | 無（沿用文件搜尋 API） |
| P13c 公開站 | • 公開文章中的文件連結：目標**有公開**時改為 `/articles/<id>/`；目標**沒有公開**時只顯示文字、不做成連結（訪客不會點到 404，也不會看到私人文件的網址）<br>• 成員閱讀入口中的文件連結改為 `/read/<id>/` | • 公開文章的回應附上該版本連到、而且目前有公開的文件 id 清單；成員閱讀入口附上可讀的文件 id 清單 |

**權限與安全**

- 反向連結與連結狀態只回傳讀者看得到的文件；訪客不會拿到私人文件的標題或 id。
- 連結解析只認本站文件的 id，不追蹤外部網址；顯示目標資訊時一律以 id 查詢目前資料，不使用連結文字。

  - 權限：Viewer 可讀、訪客不可讀；incoming 不含回收桶中的文件；outgoing 的狀態正確。
  - 永久刪除目標或來源後的行為；資料遷移補建。

  - 「連結」分頁、失效標示、移入回收桶的提醒（單份與整批）。
  - `[[` 搜尋插入、有選取時的連結文字、`/連結文件`、貼上網址自動轉換與找不到時照原樣。

  - 500 px 與深色模式。
- 驗證用的文件在結束時永久刪除。

**不納入 P13**

- 連到文件中的某一節、公開文章底部的「相關文章」、關係圖。

### 10.15 P15 細項：在原頁面新增集合

使用者回饋（2026-11-26）：新增集合時表單從畫面右側出現，不直覺。評估後採用方案 A（第 12 節第 32 點）。這項很小，和 P14 放在同一個分支 `p14-doc-outline`，一起送 PR。

**原本的問題**

### P14b 編輯時的大綱（2026-11-26）

- `markdown.ts` 新增 `outlineOf(source)`：用和預覽相同的 markdown-it 解析，回傳標題文字（不含粗體等標記）、層級、原始行號。程式碼區塊裡以 `#` 開頭的行不算標題。
- `MarkdownEditor.vue`：
  - 工具列「語法說明」前面新增「大綱」按鈕（新圖示 `outline`），快捷鍵 Ctrl+Shift+O（Monaco action `md.outline`）。唯讀時其他工具停用，但「大綱」仍可使用。
  - 打開時重新解析目前內容，尚未儲存的標題也會列出。預設選取游標所在的那一節。篩選框取得焦點，輸入的文字以空白分詞，每個詞都要符合。
  - 每一項顯示標題與行號，縮排最多三層。上下鍵選擇、可循環；Enter 或點選後游標移到那一行行尾，並把那一行捲到編輯器上方（`revealLineNearTop`），分割預覽沿用既有的同步捲動跟過去。Esc、點清單外面或再按一次按鈕會關閉，焦點回到編輯器。
  - 沒有標題時說明如何開始一個標題；篩選沒有結果時顯示「沒有符合的標題。」
  - 清單放在按鈕下方，盡量讓右緣對齊按鈕，但一律留在編輯器範圍內。分割預覽時工具列會換成兩行，按鈕靠左，因此需要這個限制。
- 語法說明的快捷鍵清單加入 Ctrl+Shift+O。
- 實作時修正：
  - 重新打開時，清空篩選文字的同時會把選取重設到第一項。改成只有輸入篩選文字時才重設。
  - 清單很長時下方被截掉，沒辦法捲動。清單改為可以縮小並捲動（`min-height: 0`）。
  - 清單原本靠右對齊，分割預覽時會超出編輯器左緣被裁掉。
- 驗證：
  - 新增 `outline_editor.py`（28 項）：
    - 工具列按鈕與提示、清單留在編輯器內、篩選框取得焦點。
    - 列出所有標題並去掉標記、程式碼區塊中的 `#` 不列、行號、預設選取游標所在的那一節。
    - 篩選、Enter 跳轉並關閉、焦點回到編輯器、分割預覽跟到那個標題、標題位於編輯器上方。
    - Ctrl+Shift+O、上下鍵、Esc 不移動游標、沒有符合時的說明、點清單外面關閉。
    - 尚未儲存的標題、點選跳轉、按鈕切換關閉、語法說明列出快捷鍵、沒有標題時的說明。
